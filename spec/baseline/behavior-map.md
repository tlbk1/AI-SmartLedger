# 当前行为基线

记录公开接口、输入输出、副作用和已知异常。首次接入只描述现状，不修复行为。

## 对外接口

- `GET /wechat`：微信服务器验签（signature/timestamp/nonce，SHA1(token)），通过则回显 echostr。
- `POST /wechat`：XML 消息 → 验签 → MsgId 幂等（重复消息不再处理）→ 文本消息进 `graph.process_message`（线程内执行，4.5s 窗口）→ 被动回复 XML；超时则先回空，结果经客服消息异步推送。`event=subscribe` 回欢迎语。
- `GET /health`：存活探针。

## 核心行为（一条消息的旅程）

1. 补投历史未送达消息（`db.drain_undelivered`）。
2. ReAct 主链：按 openid 取/建用户 → 17 个工具之一（记账、查账、建账本、邀请/审批/待审列表、切换账本、我的账本、退出、成员列表、昵称、管理员三件套、邀请码重置、主动澄清）→ 回复文本；聊天历史按用户持久化。
3. 主链失败（`AGENT_FAILURE` 哨兵）→ 兜底链：意图分类 → 记录类拒绝并要求重试；查询类走参数抽取 + SQL 聚合（收支分列、明细 top-5，与主链同口径）+ 结果摘要；闲聊直接回复。
4. 加入/审批账本时另起守护线程向对方用户推送客服消息。

## 副作用

- SQLite（WAL，活库 `db/ledger.db`；根目录另存遗留 `ledger.db`）。
- 微信客服消息 HTTP 调用（httpx，access_token 内存缓存）。
- 未送达队列：推送失败入队，用户下一条消息到达时补投。

## 已知异常/失败模式

- 主链任何异常 → `AGENT_FAILURE` 哨兵 → 兜底链兜住（哨兵是模块内字符串 `"\x00__AGENT_FAILED__\x00"`）。
- 4.5s 超时 → 立即空回复 + 异步客服推送；推送失败 → 入队待补投。
- `happened_at` 缺省兜底为 now（004 修复，防空串账目从查询窗口消失）。
- 空串/重复昵称、邀请码冲突、越权管理等在 db 层校验并返回文案（详见功能测试）。
