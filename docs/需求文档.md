# AI 智能记账助手 (AI-SmartLedger) — 需求文档

> **一句话定位**：基于 Android 通知监听 + LLM 的全自动记账系统，数据 100% 本地化，解决传统记账软件"懒得记"和"不敢用"的双重痛点。

---

## 1. 项目背景

### 1.1 痛点分析

| 痛点 | 现状 | 本项目解法 |
|------|------|------------|
| **懒得上手记** | 每次消费后要打开 App、选分类、输金额，90% 的用户两周内放弃 | 监听支付通知，全程零操作，付完钱就自动记好 |
| **隐私不敢用** | 市面自动记账产品数据全部上云，用户无法确认数据是否被转卖 | 数据 100% 本地存储，LLM 推理可选本地/自有 API，代码全开源可审计 |
| **手动分类累** | 即使自动抓取了，还要手动确认每笔的分类 | LLM 自动理解语义并分类，无需手动标注 |

### 1.2 目标用户

- **第一用户：开发者本人（自己）** — 想要零摩擦记账 + 完全掌控数据
- **第二用户：注重隐私的技术爱好者** — 愿意自部署、有一定动手能力
- **第三用户：被传统记账软件伤过的普通用户** — 想要自动记账但不敢用商业产品

### 1.3 竞品参考

- 已有商业产品（通知监听类记账 App）— 核心功能类似，**但数据上云，隐私不可控**
- 传统手动记账 App（随手记、鲨鱼记账等）— 需手动录入，留存率低
- **本项目差异化**：`全自动监听` + `LLM 智能解析` + `隐私优先架构` + `完全开源`

## 2. 核心功能

### 2.1 P0 — 最小可用版本 (MVP)

> 目标：验证"通知监听 → AI 解析 → 自动记账"的核心闭环

| 功能 | 描述 |
|------|------|
| **通知监听** | Android 后台服务监听微信/支付宝/银行 App 的支付通知 |
| **通知转发** | 将通知文本通过 HTTP POST 发送到后端服务 |
| **AI 解析** | 调用 LLM 从通知文本中提取：金额、商家、类目、时间、来源 |
| **数据存储** | 将解析后的结构化数据存入本地 SQLite 数据库 |
| **简单看板** | 一个 Web 页面展示：今日支出、本月支出、分类饼图 |
| **月度报告** | 每月 1 号自动生成上月消费分析报告（文字形式） |

### 2.2 P1 — 增强体验

| 功能 |描述 |
|------|------|
| **语音补充** | 语音补充说明（"那是和同事聚餐"），AI 更新类目或备注 |
| **批量导出** | 导出 CSV / Excel，方便用其他工具二次分析 |
| **预算管理** | 设置月度预算，超额自动预警 |
| **多账户** | 支持微信/支付宝/银行卡多个来源标记 |
| **手动修正** | AI 解析错误时，可手动修改分类或金额 |
| **智能搜索** | 自然语言查询："上个月打车花了多少" |

### 2.3 P2 — 高级特性

| 功能 | 描述 |
|------|------|
| **本地 LLM** | 集成 Ollama 跑本地模型，彻底零云端依赖 |
| |**多用户** | 多用户隔离，数据独立存储 |
| **数据同步** | 可选的端到端加密同步到自建服务器（Syncthing / WebDAV） |
| **桌面客户端** | 跨平台桌面应用（Electron / Tauri），图表更丰富 |
| **智能洞察** | "你这个月外卖花了 1500，建议控制" 类型的主动建议 |
| **信用卡账单** | 解析信用卡邮件账单，自动拆分分期 |
| **投资追踪** | 简单的基金/股票盈亏记录（可选） |

### 3.2 技术选型

| 层级 | 技术 | 理由 |
|------|------|------|
| **Android 客户端** | Kotlin + Jetpack (NotificationListenerService) | 官方 API，稳定可靠 |
| **后端框架** | Python + FastAPI | 异步高性能，适合 LLM 调用 |
| **数据库** | SQLite → PostgreSQL (后续可选) | 本地优先，零配置，单文件 |
| **LLM 提供商** | GLM API (主) / OpenAI / Claude / Ollama 本地 | 灵活切换，隐私可控 |
| **前端看板** | FastAPI 模板 (Jinja2) 或 React/Vue | 先简后繁 |
| **部署** | Docker / 本地运行 / Termux (手机本地跑) | 多种部署方式 |
| **数据分析** | Pandas + matplotlib | Python 生态原生支持 |

### 3.3 核心数据流

```
1. 用户在兰州拉面微信扫码支付 ¥18
2. Android 弹出通知: "微信支付-支出18.00元"
3. NotificationListenerService 捕获通知
4. HTTP POST → 后端 /api/v1/record
   Body: {"text": "微信支付-支出18.00元", "timestamp": "2026-08-13T12:30:00"}
5. 后端调用 LLM:
   Prompt: "解析以下支付通知，提取金额/商家/类目/来源:
            微信支付-支出18.00元"
   LLM 返回: {"amount": 18.00, "merchant": "未知", "category": "餐饮",
              "source": "微信支付", "raw_text": "..."}
6. 存入 SQLite
7. 用户打开看板 → 看到: "今日已花 ¥18 (餐饮)"
````

## 4. 数据模型

### 4.1 核心表结构

```sql
-- 交易记录表
CREATE TABLE transactions (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    amount      REAL NOT NULL,           -- 金额
    merchant    TEXT,                    -- 商家
    category    TEXT NOT NULL,           -- 类目: 餐饮/交通/购物...
    source      TEXT NOT NULL,           -- 来源: 微信/支付宝/银行卡
    raw_text    TEXT,                    -- 原始通知文本
    note        TEXT,                    -- 用户备注
    recorded_at DATETIME NOT NULL,       -- 交易时间
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    confidence  REAL DEFAULT 1.0,        -- AI 置信度
    is_modified BOOLEAN DEFAULT FALSE    -- 用户是否手动修改过
);

-- 月度报告表
CREATE TABLE monthly_reports (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    year        INTEGER NOT NULL,
    month       INTEGER NOT NULL,
    report_text TEXT NOT NULL,           -- AI 生成的报告全文
    total_spent REAL NOT NULL,           -- 月度总支出
    category_breakdown TEXT,             -- 分类明细 JSON
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(year, month)
);

-- 预算设置表
CREATE TABLE budgets (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    month       TEXT NOT NULL,           -- '2026-08' 格式
    amount      REAL NOT NULL,           -- 月度预算
    UNIQUE(month)
);
```

## 6. 简历写法

> **AI 智能记账助手 SmartLedger**（个人项目，独立全栈开发）
>
> 针对传统记账软件"用户难以坚持手动录入"和"数据隐私不可控"的双重痛点，设计并独立开发了基于 Android 通知监听 + LLM 的全自动隐私优先记账系统。

## 8. 设计原则

1. **隐私第一** — 任何功能决策的冲突时，隐私优先
2. **本地优先** — 数据本地存储是默认行为，云同步是可选增强
3. 实际需求驱动 — 只做解决真实问题的功能，不做"看起来很酷"的功能
4. **AI 是核心** — AI 不是噆头，是解决"手动分类"痛点的核心能力
5. **渐进式增强** — MVP 先跑通核心闭环，后续逐步加功能
5. **开源透明** — 代码全公开，让用户自己验证数据安全性
